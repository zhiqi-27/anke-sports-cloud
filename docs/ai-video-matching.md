# AI 视频自动匹配 v4

目标是让 Gemini 判断视频与比赛的相关性，而不是把内容硬分成“前瞻/复盘”。现有元数据规则只负责低成本地产生赛程候选和排除明确冲突；所有仍可行的候选（包括旧规则原本会自动关联的候选）都必须经过 AI。个人删除、固定和比赛生命周期仍由确定性业务规则保护。

按比赛主动发现的当前实现见[按比赛自动发现 YouTube 视频](event-youtube-discovery.md)。该链路只使用 YouTube Data API，不使用 AnySearch 或网页搜索补漏。

## 结构化输出

模型严格输出：

- 当前每个候选比赛的独立相关性置信度，候选 ID 只能来自当前赛程且必须逐一返回。同一视频可同时与多场比赛形成关联，不做第一/第二候选排名。
- `content_labels`：1–3 个简短中文标签，每个以合适的 emoji 开头，例如 `🎙️赛后采访`、`📊战术分析`。标签描述视频能看到什么，不承担前瞻/复盘分类。
- 可枚举的证据代码，供待确认界面解释。

新 AI 结果统一保存为通用 `video`。Web 日历和 ICS 系统日历展示同一组内容标签及原始 `https://www.youtube.com/watch…` 链接；不展示视频标题来替代标签。系统点击 HTTPS 链接时，由设备的 Universal Link 行为打开 YouTube App，未安装时回退网页。

## 成本优先配置

- 当前固定部署值：`gemini-3.1-flash-lite`，通过官方 Gemini `generateContent` 接口调用；模型 ID 保持配置化，后续同族模型升级不改业务代码。原计划的 `gemini-2.5-flash-lite` 对 2026-09 新建项目返回 404，未进入部署。
- 2026-09-15 官方 Standard 单价：文本/图片/视频输入 `$0.25 / 1M tokens`，输出（含 thinking）`$1.50 / 1M tokens`。实际公式为 `输入tokens×0.25/1M + 输出tokens×1.50/1M`。加入评论后的示例按每条 1,800 输入、180 输出估算为 `$0.00072`，1 万条约 `$7.20`；多候选和更长评论会增加 token。若每次都用满 1,200 输出上限，仅输出即为 `$0.00180/条`。这些是场景估算而非账单；不含重试、YouTube 与 Azure 成本。
- 只发送公开的频道 ID/名称、视频标题、最多 2400 字符简介、发布时间、最多 12 条公开顶层评论及最多 12 场候选比赛。单条评论最多 280 字符、评论合计最多 2400 字符，不发送作者名称、头像、账号 ID 或点赞数。
- 不发送用户 ID、关注配置、Feed 令牌或人工决定。
- 使用 Gemini 结构化 JSON 输出。为容纳最多 12 个候选的逐项评分，输出上限为 1,200 tokens；这是上限而非每次固定消耗。
- 相同模型、视频元数据和候选集在单个热实例内缓存，避免同一批用户重复调用。
- 模型不可用、超时、输出无效或候选超过 12 场时，中止本次业务写入并重试，保留此前有效日历；候选超限时不调用模型。
- 自动挂入的视频数量不设每场上限；每个视频独立判断，所有通过的链接都会进入产品日历和 ICS。界面未来可以折叠或分页，但不能因此丢弃链接。

## 置信度标准

模型对每个 `视频 × 比赛` 组合独立给出置信度：

| 相关性置信度 | 含义 | 产品决定 |
| --- | --- | --- |
| ≥0.90 | 与该场比赛高度相关 | 自动添加 |
| 0.55–0.899 | 与该场比赛有关联但仍需人工判断 | 进入待确认 |
| <0.55 | 泛球队内容、历史内容、冲突或与该场无关 | 静默排除，不进入备选 |

`0.95+` 应有直接比赛证据；`0.90–0.949` 可以缺少惯用日期或“前瞻/复盘”字样，但必须与该场比赛高度吻合；缺少一项关键身份、日期、联赛或 session 信息不得超过 `0.899`。

不再计算 `top1 - top2`，也不限制单场自动挂入数量。若同一视频对多场比赛分别达到阈值，则分别进入对应比赛。

Gemini 只给相关性结果，服务端统一按阈值映射为自动挂入、备选或排除，避免模型的文字决定与分数冲突。仍不能突破以下边界：候选必须由当前赛程产生、比赛不能取消、明确冲突继续拒绝、模型不能返回候选之外的 ID、用户 block/remove 和人工 pin/confirm 始终优先。

## 多模态演进

`gemini-3.1-flash-lite` 支持文本、图片、视频和音频输入以及结构化输出。v4 已加入限量公开评论，但仍未发送视频画面、音频或字幕。评论按 relevance 读取一页、去重和压缩空白后作为不可信辅助证据；模型被明确要求忽略评论中的指令、玩笑和猜测，评论不能覆盖标题、发布时间或比赛事实冲突。评论关闭时使用空列表；临时读取失败保留上次有效样本，不能使本轮视频元数据和日历写入丢失。

## 校准与调整

初始阈值不是准确率证明。启用前应使用已确认/忽略的历史样本回放；上线后按置信度区间记录确认率和误挂率，但不保存提示全文或私人配置。优先保持自动匹配 precision，再依据真实反馈调整 `0.90`，不能依据模型自报置信度直接宣称已校准。
