# 已退出范围：官方 YouTube 频道边界

更新：2026-09-16。产品已整体移除YouTube视频发现与日历挂入能力；本文只保留此前方案供历史追溯，不代表当前实现或待办。

## 产品边界

- Anke Sports 产品内只自动处理经维护者核验的球队、F1 车队和赛事官方 YouTube 频道。
- 用户关注统一落到具体球队或车队；F1赛事只作目录分组，不能直接关注。所有F1车队共享同一套大奖赛/session赛程，车队关注用于确定个人内容范围和对应官方频道。
- 不提供全网创作者发现，也不要求用户关注创作者。历史版本曾暂留创作者接口与数据；当前不保留兼容层，也不把它作为新产品入口。
- 每个官方频道必须保存 YouTube `channel_id`、HTTPS 核验证据、关联的已接入球队或赛事、维护者、核验时间、可选失效时间和启停状态。AI 不得自行把频道判为官方。
- 后台不再按每场比赛调用 `search.list`。旧事件搜索代码暂留用于历史证据和迁移，不由 Azure Timer 或本地文档 Worker 调度。
- 官方频道的视频仍按“每个视频 → 每场候选比赛”独立评分，沿用 `0.90 / 0.55` 决策阈值、最多三个展示标签、用户移除不恢复以及上游失败保留旧内容等规则。

## 官方目录与采集

维护接口 `PUT /api/v1/maintenance/channels/{channel_id}/official` 的记录新增：

- `scope_keys`：频道对应的球队、车队、赛事或系列；必须至少一个且已存在于赛程目录。
- `enabled`：暂停该频道的新内容处理时保留历史内容。

下一步由维护者逐一核验并录入 F1、英超和 NBA 官方频道，再把这些记录接到现有共享频道/WebSub 采集链路。目录录入与真实 Hub 续订、视频到比赛匹配、Feed 和设备点击均需分别验收；当前字段存在不代表已覆盖全部球队。

## MCP 边界

私人 MCP 已有 `get_schedule`、`get_event` 和 `attach_event_link`，可在用户明确选择比赛后保存 HTTPS 原始内容链接。MCP 如何搜索 YouTube 或其他内容、如何让用户确认候选，留在独立 MCP 工作中实现；产品内官方频道采集不依赖该搜索能力。
