# 关注变更预览

对应 T11 / T23。桌面“我的关注”先保留草稿，选择“预览变更”后由服务端计算影响，确认保存才修改账号配置。筛选、预览、返回和关闭均不提交关注。

## 计算与发布

`app.follow_changes.preview_follows` 与 `calendar.rebuild_feed` 共用 `select_feed_events`。预览比较当前用户最近已发布的有效投影与新配置的目标集合，计数跨演示/真实数据集；浏览筛选不限定实际订阅。

- 新增、移除、由其他关注或单场选择保留分别计数，提供各组最多10条例子和完整总数。
- 单场 include/exclude 优先，多个球队/赛事取并集。取消一个关注不会移除仍被其他选择覆盖的比赛。
- 已发布的近期历史比赛在90天窗口内继续保留以追加复盘；显式 exclude 仍可移除。已知开赛时间按绝对时间比较；仅有日期的比赛，在赛事当地“今天”不推断已经开赛。
- 目标窗口为过去90日至未来180日（日粒度）。完全无日期的关注比赛单列，不伪造开赛时间，也不计入可发布事件总数。
- 暂停时显示恢复后的预期集合，保存关注不解除暂停。上一次发布尚在队列中时，明确比较的是最近已发布内容。
- “移除”通过原投影UID的取消通知交付，不创建替代UID。`result_count` 为有效比赛数，不包含为客户端传递移除信息而保留的取消条目。

## HTTP 契约

1. `POST /api/v1/me/follows/preview`，传入 `expected_revision` 与完整 `follows`，返回 `FollowPreviewView`。认证用户由服务端确定，预览本身不修改配置、投影或任务。
2. `PUT /api/v1/me/follows` 传入相同选择、版本和返回的 `confirmation`，并提供 `Idempotency-Key`。
3. 选择对应的赛程/投影影响变化返回 `FOLLOWS_PREVIEW_CHANGED`（409），先重新预览；账号配置版本变化返回 `REVISION_CONFLICT`（409），重新读取账号关注后再选择，避免覆盖其他页面的修改。

确认摘要绑定用户、规范化选择、版本、完整影响集合及暂停/发布状态，生成后才截断展示例子；摘要不是认证凭据，也不含私人订阅地址。持续更新的赛程不会被冻结，后续上游变化仍可更新 Feed。

Web 每次保存都使用确认摘要。同一提交遇到不确定网络结果保留幂等键，成功写入后的重试优先返回原回执。为兼容已有 HTTP/MCP 调用，`confirmation` 在服务契约中仍可省略；原 MCP `update_follows` 接口本批未改动。省略摘要时，HTTP 幂等载荷不新增空字段，保留旧回执兼容性。

## 本地验收

`uv run pytest tests/test_follow_changes.py -q`：不写入、跨用户/未登录、交集与单场规则、历史、无日期、截断后完整摘要、版本冲突、幂等重试和暂停/待发布场景。

浏览器夹具：先在客户端运行 `npm run build`、`npm run start -- --port 3002`，后端运行 `uv run python -m experiments.follows_ui`，打开 `http://localhost:3003/following` 并进入本地体验。赛程、账号及数据库独立且合成，停止服务会删除临时库，不调用上游平台。

证据见 [本地验收记录](../evidence/follow-preview-2026-09-10.md)。真实 Firebase 多端、MySQL 并发、日历客户端实际移除/刷新和大规模仍需独立验收。
